The `openbat sdk` command group helps you wire `@openbat/sdk` into a target app and confirm that conversations are reaching your chatbot. It has two subcommands: `install-instructions` prints framework-specific Markdown an agent (or you) follows, and `verify` polls until the first event lands. Both run on the active chatbot pin and accept any key kind.

```
sdk                                                       [any kind]
├── install-instructions [--framework next|node|vercel-ai-sdk] [--chatbot ID]
└── verify --chatbot ID [--timeout N]                     Polls until first event
```

<Note>
The `openbat sdk` subcommands here drive the install workflow — they do not run the SDK. The SDK itself authenticates with an ingest key (`ob_live_*`), which the CLI rejects. Keep the ingest key in the target app and a read/admin/PAT key in the CLI.
</Note>

## Prerequisite — an ingest key

A chatbot must exist and the target app needs its ingest key (`ob_live_*`). Either capture it at create time with `openbat chatbots create`, or rotate a fresh one:

```bash
openbat settings keys rotate-ingest --chatbot $CB
# New ob_live_* (shown once)
```

<Warning>
The ingest key plaintext is shown exactly once, on stderr inside a "shown ONCE" banner. Store it immediately. The SDK uses **only** the ingest key — never paste `ob_read_*` / `ob_admin_*` / `ob_pat_*` into the SDK config.
</Warning>

## Generate install instructions

`openbat sdk install-instructions` prints Markdown to stdout describing how to install and wire `@openbat/sdk` in your chosen framework. An agent (or you) follows the steps.

<ParamField path="--framework" type="next | node | vercel-ai-sdk">
Target framework for the generated instructions.
</ParamField>

<ParamField path="--chatbot" type="ID">
Chatbot to scope the instructions to. Falls back to the active pin when omitted.
</ParamField>

```bash
openbat sdk install-instructions --framework next --chatbot $CB
# Markdown to stdout — agent (or you) follows the steps.
```

## Install and wire up the SDK

The generated instructions cover the same install and wire-up the agent skill bundle documents. Install the package in the target app:

```bash
npm install @openbat/sdk
```

Add the ingest key to the target app's `.env.local` (chmod 600):

```bash
OPENBAT_API_KEY=ob_live_…
```

<Steps>
  <Step title="Construct the client">
    Create one `OpenBat` instance from the ingest key in your environment.

    ```ts
    import { OpenBat } from "@openbat/sdk";

    const openbat = new OpenBat({
      apiKey: process.env.OPENBAT_API_KEY!,
    });
    ```
  </Step>
  <Step title="Record each turn">
    After each LLM turn (server action, route handler, etc.), call `recordMessages` with your own stable conversation id.

    ```ts
    await openbat.recordMessages({
      conversationId,         // your own stable id per conversation
      user: { id: userId },   // optional but recommended
      messages: [
        { role: "user", content: userText },
        { role: "assistant", content: assistantText },
      ],
    });
    ```

    `recordMessages` is fire-and-forget safe — network errors are swallowed to the console, never thrown to your handler. Latency is dominated by the response time of the OpenBat ingest endpoint.
  </Step>
</Steps>

<Warning>
`recordMessages` retries: zero. If you need durability, pair it with Vercel Workflow DevKit or a queue.
</Warning>

## Verify ingestion

After the SDK is wired up and a real chat is sent, confirm the chatbot is receiving events. `openbat sdk verify` polls `/api/v1/conversations` until `total > 0` or the timeout elapses.

<ParamField path="--chatbot" type="ID" required>
Chatbot to poll for incoming events.
</ParamField>

<ParamField path="--timeout" type="N">
Seconds to poll before giving up.
</ParamField>

```bash
openbat sdk verify --chatbot $CB --timeout 60
# Polls until first event.
# Exit 0 on success; exit 2 on timeout.
```

<Note>
`verify` runs against a **read** or **admin** key — not the ingest key the SDK uses. Keep the two key kinds separate.
</Note>

## Optional — server-managed system prompts

Fetch the live published prompt at runtime instead of hardcoding it, so you can publish prompt versions from the dashboard's experiments flow without redeploying the app:

```ts
const { template, source } = await openbat.getSystemPrompt({
  fallback: HARDCODED_PROMPT,
  conversationId,
  // mode: "instant_fallback" returns fallback immediately, fetches in BG
});
```

## Custom metadata

Custom metadata (user / organization / session / custom maps) auto-populates discovered metadata fields. Accept those fields in the dashboard before analysis starts using them.

## End-to-end placement

The install workflow sits near the end of the quickstart: create the chatbot, mint keys, configure webhooks and workflows, then hand off the SDK install and verify ingestion.

```bash
# 5. Help an agent install the SDK in a target app.
openbat sdk install-instructions --framework next --chatbot $CB
# Markdown to stdout — agent (or you) follows the steps.

# 6. After SDK is wired up + a real chat sent, verify ingestion:
openbat sdk verify --chatbot $CB --timeout 60
# Exits 0 on first event, 2 on timeout.
```

<Tip>
Every command supports `--json` for raw output (default for non-TTY stdout, so piping into `jq` always works).
</Tip>
