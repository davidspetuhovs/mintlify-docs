The exposed tool surface scales with credential strength. The key you pass in `OPENBAT_API_KEY` determines which tools the server registers: start the server with a read key and you get the read-only surface; start it with an admin key and the per-chatbot write tools appear; start it with a PAT and you also see chatbot-creation and org-level tools.

## Credential kind detection

The server inspects the prefix of `OPENBAT_API_KEY` at startup and:

1. **Refuses ingest keys** — `ob_live_*` is SDK-only; the server exits with:
   ```text
   openbat-mcp: ob_live_* keys are SDK-only — use an ob_read_*, ob_admin_*, or ob_pat_* key instead.
   ```
2. **Refuses malformed keys** — anything that doesn't match the four known prefixes is rejected before any tool is registered.
3. **Logs a startup banner** to stderr — `using <kind> key <prefix>…<hidden>, base <url>` — never the full plaintext.
4. **Filters the exposed tool list** by an authority ranking.

<Note>
There are deliberately no mutation tools for ingest keys — those remain SDK-only via `OpenBat.recordMessages`.
</Note>

## Authority ranking

The ranking is `pat > admin > read`. A higher kind can call every tool a lower kind can call. Each tool declares a `minKind`, and the server's `tools/list` response only includes tools whose `minKind` is ≤ the resolved kind.

| Resolved kind | Sees `read` tools | Sees `admin` tools | Sees `pat` tools |
|---|---|---|---|
| `ob_read_*` | Yes | No | No |
| `ob_admin_*` | Yes | Yes | No |
| `ob_pat_*` | Yes | Yes | Yes |

For the full per-kind tool list, see [Tools](/mcp/tools).

## Picking the right kind

Generate the key whose authority matches what your agent needs to do.

| Goal | Key kind |
|---|---|
| Read-only dashboards / analytics for one chatbot | `ob_read_*` |
| Manage one chatbot's webhooks / workflows / reports / settings | `ob_admin_*` |
| Create new chatbots, mint admin keys, manage your orgs | `ob_pat_*` |

### PAT sub-scope

PATs also carry a per-row sub-scope (`read` or `admin`). A read-scope PAT can run every read tool across every chatbot in your orgs but cannot mutate anything — the server will surface the write tools, but the v1 routes return 403.

<Warning>
A read-scope PAT shows the write tools in `tools/list` even though it cannot use them. If a write call returns 403, switch to an admin-scope key or an owner credential. See [Troubleshooting](/mcp/troubleshooting).
</Warning>

## Getting an API key

Generate the appropriate key in the OpenBat dashboard:

| Key kind | Where to generate |
|---|---|
| `ob_read_*` | `Settings → API Keys → Generate Read key` |
| `ob_admin_*` | `Settings → API Keys → Generate Admin key` |
| `ob_pat_*` | `Settings → Personal Access Tokens` |

<Warning>
The plaintext is shown exactly once.
</Warning>

<Tip>
Each page has a **"Copy MCP config (with key)"** button that pre-fills the launch JSON so you can paste it straight into Claude Desktop or Cursor. See [Install](/mcp/install) for the config shape.
</Tip>

To lock a PAT that can reach many chatbots down to a single one, see [Pin to one chatbot](/mcp/pinning).
